# Apple 共享 UI 耗时波动定位

最新安装候选 15：iPhone 共享 UI 的普通操作中位数约降低 10%，三轮 p95 中位数约降低 7.6%；同包新/旧 p95 比为 1.018，但轮间波动仍超门槛，总结果 inconclusive。50 次页面释放、GPU/保存和完整系统交互通过，已恢复普通入口。iPad 保持候选 10 的历史通过结果；Web 性能仍按用户安排暂缓。详见本文末尾本轮记录。

**完整性能门禁尚未通过。** 历史候选 9 已安装到 iPad，页面释放、GPU/持久化回放及完整系统交互通过；同机性能因共享首轮慢样本仍为 inconclusive。iPhone 尚未安装候选 9，不能沿用更早候选的通过结果。

## 已确认的原因

[阶段采样](phase-profile.json) 将早期慢样本定位到工程快照复制；[GC 诊断原始数据](gc-profile-iphone.json) 和 [摘要](gc-summary.json) 直接观测 V8 GC prologue/epilogue 的累计耗时。三轮旧入口各有 12–14 个同步 handler 发生 GC，共享入口各有 3–5 个；GC 常带来约 1.5–2.4 ms 停顿。少量慢样本恰好跨过 100 个样本的 p95 分位位置，使轮间 p95 在普通操作和 GC 停顿之间跳动。

诊断包具有观察开销，只用于定位，不作为性能通过证据，也没有强制 GC 或过滤 GC 样本。验收使用普通构建，诊断入口不进入最终候选。第一轮 iPad 诊断没有完成，不推断其 GC 分布与 iPhone 相同。

## 优化实现

- 预览比例修改复用已验证工程的未变分支，不再复制并重新校验整个工程；非法比例/日期仍原子失败，取消旧编译的语义不变。
- JSON 工程快照直接复制属性，减少 entries/map/临时键值数组；保留独立分支、稀疏数组及 `__proto__` 的安全处理。
- 应用层仍为每次编译创建独立快照。移动适配器将这份快照的所有权交给编译器，翻译器只修改该隔离快照。外部 `prepare/compile` 入口仍完整校验并复制输入；保存/恢复快照不受影响。
- 原生预览复用逐帧数据缓冲和按反馈槽分开的纹理绑定；尺寸/纹理变化重建缓存。每个 Pass 只保留最后一次成功的 GPU 管线，源码、Common、纹理维度变化重新编译，错误不缓存，uniform 等可销毁资源仍独立拥有。
- Native 控件比较避免整份 props JSON 序列化；UIKit 只更新变化的无障碍字段，Android 保留按钮文本变化后刷新 contentDescription 的行为。叶节点值变化不再无条件创建布局定时器；真实 `layoutChanged/loaded`、结构/布局/可见性、弹窗、键盘、环境和焦点路径继续处理。
- 性能采集期间暂时禁止自动锁屏，结束恢复原设置；进入后台即标记失败。样本数量、比例序列、预热、时间边界和判定门槛保持原样。
